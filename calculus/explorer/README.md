# Calculus → Analysis Curriculum Explorer

A single-page, single-viewport explorer of a **book-anchored progressive curriculum DAG** — the
`calc-analysis.md` research report (algebra readiness → Sobolev/PDE) made navigable through
**five relational models**.

- **27 texts · 9 tiers · 46 prerequisite edges** (38 EVIDENCED + 8 JUDGMENT) · 26 kept in the DAG
  + 1 quality-gate drop (N18 Woods, carried as a ghost) · 6 parallel sets · 2 recommended lineages.
- Built in the style + rule set of `web_manifests/` (raw HTML/CSS/JS, no framework, no build step
  at view time) for **one 16:9 4K / 27" display, fullscreen, landscape** — a single viewport with
  no page scroll.

## The five models

1. **Prerequisite DAG** — tier-layered graph; hover traces a text's full ancestor + descendant
   closure; dashed amber edges are the report's JUDGMENT calls; dashed enclosures are parallel sets.
2. **Tier ladder** — the nine-level maturity scheme, headers quoting the report's own
   name/focus/rigor per tier.
3. **Lineages & paths** — the recommended source→sink lineage with its seven seam justifications,
   the proof-novice variant, and a path finder that enumerates every directed path between any two
   texts (exact count by DP; N01 → N27 has exactly 136).
4. **Parallel sets** — the six sibling sets with shared vs partial neighborhoods **computed from
   the edge list**, so the "siblings inherit the same edges" claim is checkable (PS-2's stated
   N09 edge is honestly partial).
5. **Quality gate** — TL;DR, the 22-row kept/dropped ledger, the open register, and the caveats
   that bound what every other view may claim.

A persistent inspector dock shows the active model's method + full legend, or — when you select a
text — its citation, ISBN, tier context, parallel-set siblings, lineage membership, gate verdict,
every seam in and out, and the §9 bibliography line verbatim.

## Open it

- **Simplest:** double-click `index.html` — runs from `file://` with zero dependencies.
- **Over HTTP:** `python -m http.server 8097 --directory .`, then open `http://localhost:8097/`.

## Use it

- **Tabs `1–5`** switch models · **`/`** search · **`r`** cycles rigor · **`t`** cycles tier ·
  **`Esc`** clears.
- Hover/focus a node in the DAG to trace its closure; click any text anywhere for its detail.
- The **rigor** and **tier** selectors filter every model at once; **reset** clears all. State
  round-trips through the URL hash, so any screen is shareable.

## Rebuild the data

The fact + inference layers are generated by the Python `build/` (the only place the report text
is read — hand-transcribed into `nodes.py` / `edges.py`):

```
python build/build.py     # -> data/*.js + *.json + corpus_report.md
```

The build is also the **structural verifier**: it machine-checks acyclicity (Kahn topological
sort), tier monotonicity, the §3-table-vs-§6-DOT edge agreement, lineage hop validity,
ledger coverage, and the parallel-set shared-edge claims — the full log is
[data/corpus_report.md](data/corpus_report.md).

## Checker & tests (committed contract)

`tsconfig.json` (strict `checkJs` over the raw `.js` via JSDoc) and `package.json` pin the mid-2026
toolchain — `typescript` 6.0.x as a checker, `vitest` 4.1.x + `playwright`, `fast-check` for the
pure-core property tests (`core.js` layout/closure/paths/buckets are all pure).

```
npm run check     # tsc --noEmit
npm test          # vitest run
```

> Node was unavailable where this was authored, so `check`/`test` are the committed contract, not
> a verified run. The app ships **zero runtime dependencies** and was verified in-browser over
> HTTP at 1600×900 (DOM/accessibility/console inspection): single viewport, no page scroll, all
> five models rendering, hover-closure exact against hand-computed reachability, the path finder
> agreeing with the build's DP count (136 for N01→N27), filters/keyboard/hash round-trip working,
> no console errors.
