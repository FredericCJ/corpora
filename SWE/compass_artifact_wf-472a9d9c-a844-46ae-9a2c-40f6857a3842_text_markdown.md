# Reference Corpus: Architecture and Design of Embedded Software

## TL;DR
- This corpus assembles 90+ verified, de-duplicated resources split into two branches — **ARCHITECTURE** and **DESIGN** — each entry carrying all five sort keys (branch, embedded_relevance, hw_sw_boundary, type, verification) plus a one-line relevance note and enough bibliographic detail (authors, title, edition, year, publisher, ISBN/DOI/URL) to find it again.
- Coverage spans embedded-specific textbooks, standards (ISO/IEC/IEEE 42010, ISO 26262, DO-178C, IEC 61508/62304, EN 50128, ARINC 653, AUTOSAR, MISRA, BARR-C), landmark papers (Liu–Layland rate-monotonic, TinyOS/ASPLOS 2000), RTOS/firmware and embedded-Linux texts, ARM/vendor guides, and the general software-architecture/design classics embedded practitioners depend on.
- Recall is strongest for books and standards and thinner for university course pages, PhD theses, and practitioner blogs (search budget was exhausted mid-sweep); unconfirmed leads are quarantined in the "Unverified / to confirm" section so nothing borderline was silently dropped.

## Key Findings
The embedded software literature cleanly bifurcates into an ARCHITECTURE branch (system decomposition, deployment-driven decisions, layering, RTOS/partitioning, scheduling-as-constraint, standards, architecture description languages) and a DESIGN branch (state machines, embedded design patterns, coding standards, memory/resource techniques, driver/HAL internals). Many canonical works are embedded-specific and treat the software+hardware boundary (HAL/BSP/drivers/register access) as first-class — these are tagged `hw_sw_boundary: yes`. A substantial layer of general-purpose architecture/design classics remains load-bearing for embedded practitioners and is collected tagged `general`, per the "collect, don't exclude" rule. The only hard exclusion applied was pure hardware architecture with no software-design content.
